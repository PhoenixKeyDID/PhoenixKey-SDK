# MAGIC-LAMP Integration Gap (P0)

> **Status:** Deprecated fields pending removal. Do NOT build new features on the
> items marked below. Use the canonical vault flow instead.

---

## Root conflict

The original PhoenixKey Wallet API modelled MAGIC as a fungible wallet balance
with a per-slot accrual rate (`balance_magic`, `magic_rate_per_slot`). This is
**incorrect** — it does not match the canonical MagicLampNetwork/MAGIC protocol:

| Wrong model (custodial, deprecated) | Canonical model (vault-based) |
|---|---|
| MAGIC is a native token with a per-wallet balance | MAGIC is a number inside vault datums (`magic_batches[]`), non-transferable |
| Accrued at a per-wallet rate across slots | Generated by 4 MAGIC generators (Snapshot/Instant/Vacuum/Schedule) per vault/profile/UM |
| Claimed by calling `/wallet/magic/claim` | Consumed via the `BurnBatch` redeemer on the vault UTxO |
| Reflected in `balance_magic` on the Balance object | Read from vault datums via the canonical vault flow (MagicLampNetwork/MAGIC) |

## Deprecated surface in this SDK

The following are **slated for removal** in a future breaking version once all
consumers have migrated. Do not use in new integrations.

### `Balance` fields

| Field | Why deprecated |
|---|---|
| `balance_magic` | MAGIC is not a wallet balance |
| `magic_accrued` | Accrual is per-vault (generators), not per-wallet |
| `magic_rate_per_slot` | No per-slot wallet rate exists in canonical MAGIC |
| `last_accrual_slot` | Same as above |

### `WalletModule` methods

| Method | Why deprecated |
|---|---|
| `claimMagic()` | MAGIC cannot be minted custodially or sent to a wallet |
| `extrapolateAccrued()` | Extrapolates the wrong per-wallet rate model |

### `MagicClaimResult` type

Entire type deprecated — the custodial claim endpoint should not exist.

---

## Migration path

1. **Read MAGIC balances:** query vault datums directly via the canonical
   MagicLampNetwork/MAGIC flow (MagicSDK `VaultModule`).
2. **Spend MAGIC:** submit a `BurnBatch` transaction on the vault UTxO — not a
   `/wallet/magic/claim` HTTP call.
3. **Owner PKH bridge:** use `WalletModule.resolveOwnerPkh(userDid)` (non-deprecated)
   to get the `datum.owner` payment key hash for vault lookups.

Removal PR will be opened after:

- All known consumers (`OriLife`, `AladinWork`) have migrated off deprecated fields
